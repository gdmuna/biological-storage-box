# BSB 前端 UI/UX 审计报告

> 审计日期：2026-05-15
> 审计范围：BSB-Frontend 所有已实现页面
> 参照标准：[DESIGN.md](../DESIGN.md)（Notion 风格设计系统）
> 审计方法：页面截图 + 代码走查 + 用户视角场景还原

---

## 执行摘要

当前前端实现整体可用，但**严重低估了设计系统的执行深度**。DESIGN.md 定义了一套完整的 Notion 风格设计语言——30+ 颜色 token、14 级排版层级、10 余种组件变体——而实际页面中有效使用的不超过其 20%。视觉结果是：页面功能正确、布局过于稀疏、品牌感缺失、关键信息在空白中迷失。

用户在使用过程中最直接的感受：**"这个页面好空"** 和 **"我找不到我想要的操作"**。

---

## 一、设计系统遵循度综合评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 颜色 token 覆盖率 | 🔴 20% | DESIGN.md 定义 30+ token，实现仅 ~8 个 bsb-* 变量 |
| 排版层级执行 | 🟡 40% | 仅用了 text-2xl / text-sm 等基础 Tailwind 类，未建立完整层级 |
| 组件变体完整度 | 🟡 35% | Badge/Button/Card 基础款可用，彩色变体（pastel 卡片、tint badge）缺失 |
| 信息密度 | 🔴 25% | 所有列表页空白区域占比 > 60%，信息严重不足 |
| 空态设计质量 | 🔴 15% | 绝大多数空态仅显示一行纯文本提示 |
| 导航架构合理性 | 🟡 50% | 侧边栏分组标签语义错误，组织管理入口位置不当 |
| 无障碍 / A11y | 🟡 45% | Dialog 缺少 aria-describedby，节点类型标签使用英文 |

**整体印象**：功能基础齐全，但信息价值极低、视觉层次单调。

#### 🔴 严重问题

**整体印象**：极度稀疏，2 条数据撑不起整个页面。每条数据只有名称和子节点数，无描述、无任何操作提示。

#### 🔴 严重问题

| # | 问题 | 现状 | 期望 |
|---|------|------|------|
| R-1 | **列表信息密度极低** | 每行只有：图标 + 名称 + "N子节点"徽章 + 箭头 | 每行应展示：名称、描述（截断）、储存盒数量、创建时间、编辑/删除操作 |

| # | 问题 |
|---|------|
| R-5 | 页面标题 "库室" 偏短，建议加副标题："管理组织内的物理储存位置" |

## 三、跨切面设计系统问题

### 3.1 颜色系统背离

这是最核心的系统性问题。

| 维度 | DESIGN.md 规范 | 当前实现 | 差距 |
|------|---------------|---------|------|
| 主 CTA 色 | `#5645d4`（Notion Purple） | `#0075de`（Notion Blue） | ⚠️ 可接受的刻意偏差，但未在设计文档中说明 |
| 品牌色板 | 橙、粉、紫、绿、青色各 2 档 | 仅 1 个蓝色 + 1 个状态绿 | ❌ 品牌色板完全缺失 |
| Pastel 卡片色 | 7 种 `card-tint-*`（桃、玫、薄荷、薰衣草、天蓝、黄、奶油） | 完全未实现 | ❌ 所有功能区块卡片均为白色，缺乏视觉区分 |
| 徽章变体 | `badge-purple`、`badge-pink`、`badge-orange`、`badge-tag-*` | 只有 shadcn 默认 `Badge`，样式单一 | ❌ 危险级、操作类型、状态标签无法通过色彩传达语义 |
| 语义色 | `semantic-warning: #dd5b00`（橙）、`semantic-error: #e03131` | 使用 Tailwind `yellow-`、`red-` 等随机类 | ❌ 语义颜色不一致，品牌认知无法积累 |

### 3.2 排版层级未执行

DESIGN.md 定义了 14 级排版层级（`hero-display` 80px → `micro-uppercase` 11px），当前实现：

- 所有页面 `h1` 均为 `text-2xl`（24px），与 DESIGN.md `heading-1`（48px）或 `heading-2`（36px）差距悬殊
- 副标题一律 `text-sm text-bsb-text-tertiary`，无法区分 `subtitle`（18px/400）与 `caption`（13px/400）
- **未引入** `font-display`（Plus Jakarta Sans）用于大标题——代码中虽定义了 `--font-display`，但页面大多数标题仍用 `font-sans`
- 字重：DESIGN.md 建议 heading 用 600，button 用 500，body 用 400；实现中混用 `font-semibold`、`font-bold`、`font-medium`，无规律可循

### 3.3 面包屑导航设计错误

**现状**：面包屑第一段"Biological-Storage-Box"是指向 GitHub 仓库的外链（`https://github.com/gdmuna/biological-storage-box`）。

**问题**：
1. 在生产应用中，面包屑应反映**应用内的层级路径**（如"首页 > 储存盒 > 样本盒A-01"），而非外链
2. 用户误点可能意外跳出应用
3. 第二段为当前页名称且被设为 `disabled`，不可点击——但面包屑的末项本就不应可点，这是正确的，只是前项逻辑错误

**期望**：第一项改为可点击的"首页"/"仪表盘"，指向 `/dashboard`；去掉 GitHub 链接。

### 3.4 侧边栏导航分组语义错误

**现状**：侧边栏有唯一的分组标签"试剂管理"，其下包含所有 8 个导航项：仪表盘、库室、储存盒、试剂、试剂类型、操作日志、节点图、**组织**。

**问题**：
- "仪表盘"和"节点图"不属于"试剂管理"语义范畴
- "组织"是管理性功能（企业架构），混在操作性功能中层级混乱
- 分组标签显示太小（`caption` 级），而 DESIGN.md 中分组标签应使用 `micro-uppercase`（11px/600/1px letter-spacing）

**期望**：
```
▸ 核心功能
  仪表盘
▸ 库存管理
  库室 / 储存盒 / 试剂 / 试剂类型
▸ 分析与记录
  操作日志 / 节点图
▸ [组织] → 移至 TeamSwitcher 下拉菜单
```

### 3.5 空态设计体系缺失

**现状**：所有页面的空态（无数据时）仅有一行灰色文字提示（如"暂无储存盒，点击'新建'创建第一个"）。

**问题**：空态是用户首次进入系统时看到的第一个页面状态，直接影响入门体验和转化率。一行文字无法传达：
- 当前空白是正常状态还是异常（数据未加载完成？权限不足？真的没有数据？）
- 下一步应该做什么（通过什么路径解决空态）
- 品牌温度（冷漠的空白 vs. 友好的引导）

**期望**：建立统一空态组件 `EmptyState`，包含：插图（SVG icon）+ 标题 + 说明文字 + 主操作按钮（可选）。

### 3.6 Dialog/Modal 无障碍问题

**现状**：多处 Dialog 触发控制台警告：
```
Warning: Missing `Description` or `aria-describedby="undefined"` for DialogContent.
```

**影响**：辅助技术（屏幕阅读器）用户无法理解弹窗目的；违反 WCAG 2.1 AA 标准。

**修复**：所有 `DialogContent` 必须包含 `<DialogDescription>`（可视觉隐藏：`sr-only`）。
